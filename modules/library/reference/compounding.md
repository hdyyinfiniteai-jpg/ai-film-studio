# 复利模型

## 一、为什么方向 C 的 ROI 最高

A 和 B 优化的是**单个项目内部**。C 优化的是**项目之间**。

你同时在跑互动影游、短剧、喜剧、古装、舞台剧多条线。
跨项目复用的杠杆比任何单项目优化都大 —— 而且它是唯一一个**不会随项目结束而归零**的投入。

## 二、成本结构

```
一部片的总成本 = 资产生成成本 + 视频抽卡成本
                    ↑ C 优化这个        ↑ A 的 failure-codex 优化这个
```

注意 codex 同时属于两边 —— 它既是 C 的第五个库，也是 A 的参数来源。
**这就是为什么 codex 应该第一个建。**

## 三、复用率与边际成本

```
复用率 = 命中库的资产数 / 本片需要的资产总数
资产成本 = Σ(命中的 × 变体价) + Σ(新建的 × 全价)
```

单价（`config/health-thresholds.json` 可改）：

| | 全价 | 变体价 | 比 |
|---|---|---|---|
| 演员 | $24.0 | $3.2 | 7.5× |
| 场景 | $9.6 | $2.4 | 4.0× |
| 道具 | $1.6 | $1.6 | 1.0× |

**演员的复用杠杆最大** —— 这就是 Persona Vault 值钱的原因。

## 四、曲线

```
第 1 部：库是空的，全部从零建                        100%
第 2 部：美学复用 1 套，微节拍 60%，失败档案全复用      ~65%
第 3 部：+ 场景库部分复用，+ 演员跨项目串场            ~45%
第 N 部：新增的只有本项目独有的角色和场景              ~30%
```

`vault.py compound` 输出实测值。**实测低于估计曲线时，去看 health 的覆盖度热力 ——
通常是某个库有空洞。**

## 五、库腐烂的三个征兆

| 征兆 | 检测 | 处理 |
|---|---|---|
| 同一资产被建了多份 | `health` 撞库检测 | 合并，保留 used_in 并集 |
| 条目缺关键字段 | `health` 完备度 <80% | 补齐，或标记为草稿不参与 checkout |
| 长期未被引用 | `health` 陈旧 >400 天 | **不要删**。归档即可 —— 删除是不可逆的 |

## 六、什么该入库，什么不该

| 该入库 | 不该入库 |
|---|---|
| 角色本体、声纹、状态变体 | 本片的场次归属、走位图 |
| 场景视图、光线档案、色板 | 本片的服装状态、时间连续性 |
| 道具句柄与规格 | setup/payoff 的场次编号 |
| 美学模板 | 控制性理念（那是这一部片的） |
| 微节拍句 | 具体台词 |
| 失败模式与防御句 | 单条提示词全文 |

**判据一句话：去掉项目名之后还成立的，才是资产。**
