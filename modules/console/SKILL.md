# director-console · 导演决策台

方向 A 的假设是「人写规则，机器执行」。
方向 B 的假设是：**AI 电影的瓶颈不是执行，是判断。**

一个 15 秒镜头有几十个可选项。系统的价值不是替你选，
而是**把选项摆出来，并说清每个选项的后果和抽卡风险**。

## 四条纪律

1. **系统穷举并预判，但绝不替你选。**
2. **每个选项后面挂着工程后果** —— 成本增量（美元）+ 抽卡风险等级 + 结构影响。
   这是本 skill 与普通「给你几个选项」的唯一区别。
3. **不可逆选项强制留痕。** 反用映射、删场、结构性改动 —— 不写理由拒绝作答。
   反用是选择，不是遗忘。
4. **样本不足的风险标签一律标『拍脑袋』。** 否则你会信任一个猜出来的数字。

## 决策疲劳协议（本 skill 最核心的工程）

一部 90 分钟片有 200+ 分叉。**全问必然崩** —— 这是方向 B 唯一的真实风险。
三级分流：

| 级 | 含义 | 谁来答 |
|---|---|---|
| **S 策略卡** | 全片答一次，答完自动预填大量场次卡 | 人，最先答 |
| **A 必答卡** | 两选项后果差异大，机器不得代答 | 人 |
| **B 托管卡** | 按策略卡默认预填，随时翻牌改 | 机器预填，人可翻 |
| **C 自动卡** | 后果差异低于阈值，不进界面，只记日志 | 机器 |

**外加决策预算**：每 10 分钟片长 ≤6 张必答卡。超出的 A 卡**真降级**为 B（不是嘴上说说），
按影响面排序保留最高的几张。

**影响面评分**
```
impact = 结构影响×2.0 + 成本跨度/8.0 + 影响提示词条数/4.0 (+1.5 若不可逆) (+4.0 若全片级)
```

## 十三类决策卡

| 层 | 卡 |
|---|---|
| 策略（S） | 摄影机默认站哪边 · 观众领先还是同步 · 提示词短而多抽卡还是长而高精度 |
| 故事 | 是谁的价值在动 · 呼吸场保留还是删 · 结尾留白还是说明 |
| 表演 | 转折反应向内还是向外 · 延迟还是即时 · 面具在第几拍裂开 |
| 摄影 | 转折在镜头内还是靠剪辑 · 映射照办还是反着来 |
| 分镜 | 拆还是合 · 插入镜头留还是删 |

**表演层拆成两次二元问**（向内/向外 → 延迟/即时），
决策质量显著高于「惊讶是哪一种」的四选一。
二元问题优于开放问题 —— SCREENWRITER 的纪律，此处升为全局。

## 用法

```bash
cd tools
python3 console.py deal                    # 穷举分叉，分流，按影响面排序
python3 console.py show STRAT_INSERT       # 看完整卡（含后果预判）
python3 console.py answer STRAT_INSERT A   # 作答
python3 console.py answer CAM_OVERRIDE@31 B --why "此处反用：让观众和他一起被钉住"
python3 console.py auto                    # B 级批量托管
python3 console.py apply --prune           # 回写 project.json（--prune 才真删场次）
python3 console.py profile                 # 决策日志 → 导演偏好画像 → my-style.md
python3 console.py render                  # HTML 决策台
```

## 与 film-pipeline-orchestrator 的关系

**共享同一份 `project.json`。** 决策台写 `focal_character` / `mask_crack_beat` /
`mapping_override` / `planned_prompt_count` / `insert_shots` / `director_policy`，
产线读它们并执行。

典型顺序：
```
orchestrator run S1        产线算出场次数据（价值/秒数/情绪轨迹）
console      deal→answer   导演在数据基础上做判断
console      apply         判断回写
orchestrator all           带着判断重跑，出片
```

## 为什么适合互动影游

互动影游的分支结构本身就是一棵决策树。
决策卡机制和分支叙事**天然同构** —— 你在决策台上做的每一次二元选择，
形式上就是玩家将要面对的那种选择。决策日志可以直接当作分支设计的草稿。

## 已知限制

- **风险系数目前全是拍脑袋的**（`config/risk-table.json` 里 n=0）。
  界面会诚实标注。跑满 15 次同类生成后，用实测覆盖 `mult` 和 `n`。
- **不适合外包协作** —— 决策必须来自同一个大脑，否则日志沉淀出的偏好画像是噪音。
- `profile` 需要同类卡 ≥5 次且集中度 ≥70% 才认定为稳定偏好，
  否则只显示「样本不足」，不写 my-style.md。
