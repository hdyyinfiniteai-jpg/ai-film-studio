# 决策疲劳协议

> 方向 B 的唯一真实风险不是"系统不够聪明"，是**人会累**。
> 一部 90 分钟片 200+ 分叉，全问必崩。这份协议是本 skill 存在的前提。

## 一、三个失效模式

| 失效 | 表现 | 后果 |
|---|---|---|
| **决策疲劳** | 前 30 张认真答，后 170 张全按推荐 | 比不问更糟 —— 推荐值被当成了选择 |
| **虚假精度** | 相信"抽卡风险：高"这个标签 | 但那个数字是猜的（n=0） |
| **不可逆遗忘** | 三个月后不记得为什么第31场用了静止广角 | 改片时把它"修"回去了 |

## 二、对应的三个机制

### 机制 1 · 三级分流 + 决策预算
```
S 策略卡先答 → 大量场次卡因此有了默认值 → 只有默认值明显不合适的才升 A
A 必答卡受预算约束：每 10 分钟片长 ≤6 张
超预算的 A 卡真降级为 B（写回 deck.json，标 downgraded=true）
```

**关键：降级是真的降级。** 如果只是"不显示"，导演会以为自己答完了。

### 机制 2 · 置信度必须可见
```
[实测]   ← n ≥ 15，可以信
[拍脑袋] ← n < 15，界面用暗黄色标注
[基线]   ← 无已知风险因素
```

一开始所有标签都是「拍脑袋」。**这不是缺陷，是诚实。**
用 `orchestrator run S7` 积累样本后覆盖。

### 机制 3 · 不可逆选项强制留痕
```bash
$ console.py answer CAM_OVERRIDE@31 B
✖ 该选项不可逆（反用映射/结构性改动），必须用 --why 写一句理由
```

覆写理由会进 `profile` 的「这些是你真正的作者性所在」区块。
**一部片跑完，这个区块就是你的导演阐述初稿。**

## 三、什么时候该增卡，什么时候该减卡

**增卡的信号**：同一类失败在成片阶段反复出现，说明那个分叉当时没被问。
**减卡的信号**：某类卡连续 10 次答案相同 → 它应该降为策略卡，全片答一次。

`profile` 的集中度百分比就是这个信号：**≥90% 且 n≥10 的卡型，应当合并为策略卡。**
